# ecbx 标准文档

**crate**：`ecbx` v0.1.0 | **角色**：ECB 源事实类型层（provider） | **状态**：非 package stable

> 本文件是 `ecbx` 的能力标准；其 `##` 章节与 `tests/sdd_spec.rs` 的 `// SPEC-MAP:` 逐条 1:1。
> 采集范围权威是 `specs/adapter/ecb.md`；跨源语义归
> `specs/005-macro-data-source-crates/contracts/cross-source-routing.md`。

## 1. 数据类型标准

- 数据类型只有 7 个取值，逐字取自 `specs/adapter/ecb.md` §1.2：
  `ZERO_SPOT`（零息即期曲线）、`FORWARD`（隐含远期）、`POLICY_RATE`（MRO/DFR/MLF）、
  `RFR_OVERNIGHT`（€STR）、`CB_BALANCE_SHEET`（周报资产负债表）、
  `MONEY_STOCK`（M0/M1/M2（BSI））、`DEPOSIT_FACILITY`（存贷便利）。
- 类型码与中文说明都由 `EcbDataType::code` / `EcbDataType::description` 暴露；`from_code`
  只接受这 7 个字面值，其余一律 `Invalid`。
- 协议只有名字：`EcbProtocol` = `SDMX-JSON` / `SDMX-ML` / `CSV`。
  **本库不含任何端点**——清单把全部端点许可登记为 UNKNOWN，规划端点 ≠ 访问合同。
- 不在本库登记限流数字、Header、凭据字段或统计码全集。

## 2. 身份形与维度顺序标准

- 身份形 = `dataflow + DSD + 规范化维度键`，再叠加 `indicator + subject + period + vintage`；
  `EcbObservation::source_series_id` 输出完整串。
- 规范化维度键由 `EcbDataflowId::declared_dimension_key` 产出，形如 `DIM_A=VAL_A.DIM_B=VAL_B`，
  **顺序即调用方声明的顺序**。
- 校验要求 `dataflow` / `dsd` 非空、至少一个维度、维度键与取值非空且维度键互不重复；
  重复维度键返回 `SemanticallyRejected`。
- **手填维度顺序不得冒充官方 code list**：`attest_official_dimension_order` 对任何输入
  （含空切片）恒返回 `NotApplicable`。清单把官方 DSD / code list 登记为 `absent`，
  离线属性键白名单 ≠ 元数据已实现。
- 顺序不同即身份不同：`DIM_A=VAL_A.DIM_B=VAL_B` 与 `DIM_B=VAL_B.DIM_A=VAL_A` 不得互相冒充。

## 3. 曲线路由标准

- `ZERO_SPOT` 与 `FORWARD` 是 YC dataflow 的**曲线点**，`is_curve_product` 为 `true`。
- 曲线点**可以被持有**（类型层保留它们），但**不得在本库晋级**：
  `ensure_not_curve_product` / `reject_curve_promotion` 对曲线点返回 `RoutedElsewhere`。
- 点映射须 `yieldx` 批准；本库不复制 kernel、不把曲线点洗白为普通观测。
- 其余 5 类不是曲线产品，守卫放行。

## 4. 授权与 publication 标准

- 本源 `authorization = unknown`：**无 Owner 签核文件**，全部端点许可 UNKNOWN。
  `registered_evidence()` 恒为 `None`，`current_authorization()` 恒为 `Denied`。
- fail-closed 判据：证据缺失、证据出处为空、签署者不明、覆盖范围不明、有效期不明、
  证据已过期 —— **一律 `Denied`**；MUST NOT 默认放行，MUST NOT 以「清单里写了」替代证据。
- 判定是**只读结论**：不改写清单或名册的任何登记值。
- `ensure_authorized` 把 `Denied` 映射为 `EcbErrorKind::AuthorizationDenied`。
- publication 语义恒为 `Date` + `Inferred` + `NotEligible`：本层不认识官方 vintage 面、
  不持有发布日历，故只能是推断层且不具正式 PIT 资格；**禁止**补造 `00:00 UTC` 把
  `Date` 伪装成 `Instant`。
- ECB / 日本 MOF 财政类的写入主权为 `pending`（未决），`claim_fiscal_write_authority`
  恒返回 `WriteAuthorityDenied`——双方均不得主张权威写入。

## 5. 输入形态与解析边界

- 输入形态：JSON 文档 `{ "_synthetic": <bool>, "_note": <string>, "observations": [ … ] }`；
  观测字段名取自 `specs/adapter/ecb.md` §1.3 与 `specs/数据清单/ecb.md` §2.3。
- 解析入口只接受文本：`parse_ecb_observations(input: &str)`，
  **不接受** URL、HTTP 客户端、认证参数。
- **未知字段原子失败**：顶层与观测层都启用 `deny_unknown_fields`；一条失败即整体失败，
  不返回部分结果。
- **重复身份一律拒绝**：以 `source_series_id` 为身份，重复即 `SemanticallyRejected`；
  **本库选择拒绝而不是去重**。
- 缺失值必须具名：`value` 为 `null` 时携带源侧 `obs_status` 原文（`Missing` 的具名原因），
  源侧未给状态则记 `Unspecified`；**绝不静默转 0**。
- 日期只接受严格 `YYYY-MM-DD`（月、日两位补零），拒绝 `2026-2-3`、`2026/02/03`、
  `2026-02-30` 与带时间部分者。
- 输入必须显式标注 `_synthetic = true` 且 `_note` 非空：本层只处理合成样本，
  拒绝把未标注输入当作源数据。
- JSON 语法错误的消息只带行号、列号与错误分类，**不回显原文片段**（避免把凭据或
  整行配置源码带进错误消息）。

## 6. 合成夹具声明

- `tests/fixtures/` 下的全部文件都是**本特性自拟的合成样本**，**不是真实源数据**，
  **不构成任何证据**；每个文件带 `_synthetic: true` 与 `_note` 说明。
- 夹具的字段名与结构对齐清单声明的事实；其中 `dataflow` 取自清单字面（如 `YC`、`BSI`），
  而 `dsd`、`indicator`、`subject`、维度键值、单位等一律使用显式占位（`DSD_SYNTH`、
  `IND_SYNTH`、`DIM_A=VAL_A`、`SYNTH_UNIT`），因为清单未给出这些取值。
- **禁止**把夹具数值表述为「实测」「核验 PASS」或任何证据等级。
- 夹具值一律不得被当作官方 code list、官方 DSD 名或真实观测。

## 7. 非目标与门禁

- 非目标：不实现联网采集与 SDMX 客户端；不实现官方 DSD / code list；不把曲线点晋级；
  不做派生指标（净流动性、利差、Credit Impulse、z-score）；不做单位换算；不读凭据与环境变量；
  不建共享 core crate。
- 「能力标准」在本库只到「类型 + 离线解析 + 校验 + fail-closed 判定」为止；
  `production_decision = NO-GO`，清单 COMPLETE ≠ ship。
- 门禁：

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo package --no-verify
```

- 三类测试：`tests/tdd_contracts.rs`（`// TDD-PROBE:` 四列表，覆盖全部公开入口）、
  `tests/sdd_spec.rs`（本文件 `##` 章节 1:1）、`tests/aidd_boundary.rs`（`// AIDD:` ≥5 条）。
